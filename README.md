# TraceClimate

An environmental data workbench for researchers and community monitoring teams: import daily temperature data, detect unusual values, and preserve a portable evidence chain.

Built for the IEEE ClimateChain Global Hackathon, **Climate Data & Environmental Monitoring** track. Entrant: Bharath Gelivi (Devpost: BharathGelivi). Built on 9 October 2026 with substantial Codex AI assistance for research, design, implementation, documentation and testing.

## Run

Requires Node.js 22 or newer; no dependencies, paid services, API keys, or account setup.

```
npm start
```

Open http://127.0.0.1:4173. For tests: `npm test`. Deploy the contents of `dist/` to any static HTTPS host. HTTPS or localhost is required for Web Crypto.

## Modules

- `dist/core.mjs`: CSV validation, robust rolling median/MAD model, NASA POWER importer, canonical SHA-256 chain and verification.
- `dist/app.mjs`: data state, file import/export, rendering, integrity verification and tamper demonstration.
- `dist/index.html`, `dist/style.css`: responsive, labeled interface and timeline.
- `tests/core.test.mjs`: data, model, source and integrity tests.
- `PLAN.md`: project scope, module acceptance criteria and event comparison.

## Judge walkthrough

1. Select **Load anomaly demo**. This is explicitly synthetic. Expect 45 readings, 1 flag at 29 September, 53.4 °C.
2. Inspect the timeline and the explanation in the review queue. Toggle all readings to see model warm-up.
3. Select **Seal this dataset**. Copy the root to a separate trusted location; export the JSON.
4. Select **Verify chain**: all 45 records should match.
5. Select **Test tampering on a copy**: a changed reading should fail. The original remains valid.
6. Open the downloaded evidence JSON and paste the independently saved root. Verify again.
7. Optionally import live NASA POWER data using the default Bengaluru coordinates and historic date range, or your own strict `date,value` CSV. Invalid input leaves the last valid dataset intact.

## What the model does

This is a robust statistical anomaly detector, not a generative model. For each reading it trains a baseline on up to 14 **preceding** values, calculates median and MAD, scales MAD by 1.4826, with a 0.5 °C minimum scale to avoid division by zero, and flags deviations over 4.5. Seven preceding readings are required. It is a transparent baseline suitable for a prototype, not a validated climate forecasting or fraud detection system. Natural extremes can be flagged, and slow drift can be missed. No values are automatically corrected.

## Evidence and threat model

The header includes source metadata, timestamp, units, model and count. Each block contains its reading, analysis, index and predecessor hash. Canonical object serialization sorts keys, preserving array order. The final hash is the root. Verification checks count, order, reading validity, recomputed analysis, block hashes and an independently trusted root.

The root must be retained separately: an attacker who can replace the bundle **and** the trusted root can rewrite history. This local evidence chain has no decentralized consensus, deployed blockchain, on-chain anchor, trusted timestamp, institutional signature or sensor attestation. It proves integrity relative to a trusted root, not the truth of the source. A future adapter could anchor roots in a public ledger without publishing readings; that adapter is not implemented or claimed.

## Data and privacy

Uploaded files stay in browser memory. No upload, analytics or persistent dataset storage is used. NASA requests send user-selected coordinates and date range directly to the public NASA POWER API. NASA data is gridded daily 2 m air temperature (T2M), not individual ground sensor data and not evidence of long-term climate change. Missing values of −999 are omitted, and outages surface as errors. Google Fonts is used for optional typography; system fonts work if unavailable.

NASA documentation: https://power.larc.nasa.gov/docs/services/api/temporal/daily/
